# Local workflow review lessons

- Keep the reviewed estimate in its own persistent control. Setup, cancellation, errors and progress must not overwrite the amount that a user is about to authorize.
- One explicit Generate action can acknowledge the article estimate and retained holds. Keep optional private diagnostic consent separate; simplifying cost confirmation must not silently enable sensitive capture.
- Validate export paths and media tools before starting a durable job. Repeat the checks at export, because preflight cannot eliminate later filesystem changes. Never overwrite an existing destination.
- Preserve an uncertain job start as uncertain. A missing acknowledgement or local failure is not permission to re-enable Generate or resend accepted text.
- Test real dynamic dialogs, cancellation, visible primary controls and output recovery at the actual display scaling. Backend and presentation tests alone do not establish usability.
- Use an ordered file-based concat manifest for large article jobs. Generated relative filenames keep command lines bounded and exclude user paths from concat directives. Verify input hashes, homogeneous media, full decoding and the final output before publishing it.
- Treat required-run catalog refreshes differently from ordinary connection checks. Opening a dialog must not silently consume a restricted refresh. A stopped run must not offer an unconditional retry.
- A reboot resets monotonic time. Preserve the original run's stop, evidence, counters and spending; use an explicitly reviewed transition rather than resetting watermarks or weakening an active guard. Nonfinancial preparation and paid execution need distinct authority.
- Finish preparation before opening a short execution window. Never extend an expired window implicitly or treat elapsed setup time as permission to retry.
- Retain a typed actionable local guard reason before redacting exception prose. Missing verified voice selection should remain distinguishable from an expired catalog, denied credential, invalid scope or provider rejection.
- Distinguish synthetic success, real native media processing, installed UI acceptance and actual provider narration in every result. A decoded test tone is not a delivered narrated article.
- Verify transferred patches by immutable identity and hash. Merge overlapping changes manually when local work has newer privacy, progress or recovery behavior. Preserve the prior source and release before changing it.
- Use the pinned SDK and the correct existing package cache for isolated tests. Disable optional SDK first-run certificate generation and telemetry explicitly; a temporary CLI home alone does not prevent those side effects.
- Validate and replay journal records with identical rules before committing. In particular, reject noncanonical operation IDs before a write rather than creating history the reader cannot reopen.
- Exercise hash-verified modules through the real isolated command bridge. Direct imports do not reproduce a module namespace created with `exec`; locate verified siblings from the compiled function's source filename when `__file__` is intentionally absent.
- Distinguish trusted-clock measurement precision from wall-versus-monotonic drift. Never claim subsecond certainty from a whole-second source, and always apply the conservative time bound to deadlines.
- Qualify rollback precisely when old readers cannot understand newer journal records: preserved blocked predecessor bytes are a safety fallback, not proof of a functioning old application or restored authority.
- Treat a real provider rejection as a required end-to-end fixture. The provider's actual terminal disposition can differ from a mock's convenient retryable enum; preserve its exact outcome while separately deciding whether a changed, source-preserving request is authorized.
- Do not replace one arbitrary workflow limit with a larger arbitrary number. Error history, splitting, readback, export and resumption must agree on progress and genuine termination conditions. Preserve historical counters while deriving request bounds from the spending allowance and split depth from finite, strictly shrinking source ranges.
- Verify durable trend records through the production logging registration, ordinary filtering, restart and actual file readback. A logging method call or an HTTP-body read is not proof that useful history was retained.
- Keep safe structural history separate from sensitive provider responses: indefinite content-free trend records do not silently extend a previously agreed 24-hour full-response privacy limit.

Apply these practices to the other maintained projects as relevant, while preserving each project's own privacy, licensing, release and authorization requirements.

## Completed narration and release follow-through

- A cached capability can expire between an early freshness check and later compilation. Check the actual pre-reservation boundary, including recovery children. Refresh only through the existing same-account, same-source and same-voice path; do not repeat an approval, reserved request or uncertain submission.
- Progress by source part and progress by internal split request are different. A source ordinal can remain unchanged while smaller accepted pieces accumulate. Inspect durable receipts and typed stages before calling the job stalled.
- Preserve deeper split depth in derived reports as well as the permanent records. Report omitted sources from bounded analysis explicitly; do not describe a bounded scan as the entire retained history.
- Distinguish conservative spending holds from provider invoices. Free allowances, credits, billing delay and currency conversion can make the invoice different; do not report internal holds as money actually charged.
- Verify full source coverage, full decoding and the final artifact hash against its durable completion receipt. State listening checks separately; a successful decoder does not prove that a person listened to the recording.
- Discover the registered application identifier and test a normal cold launch before handing a launch problem back to the user. A helper launch failure alone does not prove that the installed executable is missing.
- Article synthesis diagnostics are not proof that authentication, catalog, deployment and export errors retain every useful detail. Keep an explicit boundary-specific coverage statement and never claim all logging is complete from one successful transport test.
# Native continuation after terminal diagnostic release

- A separately installed native reservation-resume admission must retain its exact unexpired catalog snapshot when Create MP3 reopens, even after the diagnostic gate is retired. Verify fresh catalog and empty-probe provenance; never extend the original lifetime or retain changed evidence.
- Native review JSON is metadata, not authority. Historical diagnostic policies can include hashes of raw JSON subobjects. A private policy assembler must preserve the verified original historical bytes, compare their parsed content with the new native draft, and never repin old hashes merely to accommodate formatting.
- Exercise the actual cold-start path after admission. A warm-process resume test cannot reveal an automatic bootstrap that replaces the newly admitted snapshot.
- PowerShell scripts need explicit success/readback handling. A successful script without a native process can leave an earlier LASTEXITCODE intact; do not mistake that stale value for a failed backup or repeat completed work.
