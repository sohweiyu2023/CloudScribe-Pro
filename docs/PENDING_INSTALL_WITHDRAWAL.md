# Interrupted unused diagnostic installation

This administrative recovery is separate from narration authorization. It can
restore the exact retained predecessor installation after a claimed, unused
diagnostic successor failed during file replacement. It grants no reservation,
capture, catalog refresh, admission, new window or provider request.

Use only an independently reviewed plan and the supported
`Install-CloudScribe.ps1` administrative mode. The plan binds the original sealed
handoff, immutable old/new gate evidence, both register heads, source/interpreter
hashes, complete installation inventories, retained required-marker bytes and a
distinct administrative approval. Evidence and source files must remain outside
the installation, stage and displaced roots. The old gate is derived from its
original activation, not from the installed slot that was replaced.

The inactive replacement journal may contain the supported installer's sealed
pre-install `check` events after `start`. Only these two event types are allowed;
the complete chain is authenticated and the exact reviewed head must still match.
Activation, claims, completions, stops, malformed checks and any changed head are
rejected. No journal row is filtered, reset or rewritten to manufacture this state.

Before any restoration, the operator holds the app instance, database, existing
sidecars and administrative installation leases. It verifies the unchanged
database, financial projection, accepted media, failed parent and absence of a
child, accepted target or uncertain submission using the production bridge. A
durable withdrawal claim blocks the old handoff before directory replacement.
The original backup is copied, never consumed; the incomplete installation is
moved to a second retained directory. Profile data, vault entries and financial
records are not restored or rewritten. Only the required-marker control file is
restored in the profile.

Completion requires actual app/infrastructure hashes, gate, install marker,
required marker, full inventories and financial/media evidence to match. Journal
history is append-only. Historical counters, stopped reason and trusted clock
watermark remain intact. The orphan successor stays inactive. The restored
predecessor remains blocked; restoration is not permission to run it.

After an interruption, reconcile the exact journal and filesystem first. Resume
only the same admitted withdrawal when its claim is still pending and the
observed intermediate state matches. Partial or changed copies, mismatched
identities, unavailable locks, uncertain outcomes and missing evidence stop the
operation. If completion may already have committed, reconcile read-only rather
than repeating a claim or completion. Retain all original evidence and backups.

`-ValidateOnly` uses administrative inspection. It can open/create administrative
lease files; it does not create paid authority or restore files. This is not a
promise of literally zero filesystem activity.

A later diagnostic needs a separately approved fresh scope and capture consent,
with newly frozen predecessor evidence outside the replacement root. Neither the
withdrawn diagnostic approval nor administrative approval can authorize it. No
automatic renewal, paid retry or continuation is provided by this recovery.
