# Narration evidence and recovery lessons

These rules apply to provider-backed features across projects, not only speech generation.

- Keep provider acceptance, request outcome persistence, audio saving, assembly, decoding and final delivery as separate observed stages. A local failure after provider acceptance is not permission to synthesize again.
- Preserve the useful provider explanation when received under the approved protected-capture scope. Log safe identity, status, correlation and retention/completeness metadata routinely. Never claim an explanation was retained merely because the HTTP body was read.
- Explicitly distinguish queued private writes from durable readback, and report unavailable, redacted, omitted and truncated evidence. Successful response metadata must not evict error explanations. Do not impose an error-count stop or count-based error rotation; check the actual protected storage and report real failures.
- Canonical protocol status values can be retained as structured evidence; unknown encoded strings, credentials, article echoes and audio still require privacy filtering. Do not reconstruct a discarded historical field from a later code fix.
- A documented request-byte limit is not a sentence limit. Do not invent a numeric model threshold. Sentence markers preserve structure but do not guarantee provider acceptance.
- Record content-free structure using an explicit measurement version: exact wire/input byte counts, source scalar counts, input mode, sentence distribution, voice and correlation. Join to durable outcomes and capture status. Unknown split depth must be marked unavailable rather than guessed.
- Routine debugging logs may rotate. Durable privacy-safe trend records need a separate append-only history without automatic age or count deletion. Full protected responses retain their separately agreed privacy expiry. Report gaps, completeness, code/model/input-mode changes and sample size; do not infer a universal optimum or causation from a few successes and failures.
- Split only confirmed, reconciled sentence-length rejections using source-preserving natural boundaries. Require strict range shrinkage, exact reconstruction and a finite source-derived termination bound, not an arbitrary two-level stop. Count bounds derived from the remaining monetary allowance must not bind before that allowance. Never retry an uncertain submission, overwrite accepted output, silently extend a window or mint authority from an error.
- Exercise deeper recovery through accepted-media readback and final assembly: lifting the planner limit alone can leave old depth or leaf-count checks that reject valid saved audio later.
- When the user explicitly chooses completion- and budget-bound execution, transition through the exact clean predecessor checkpoint. Keep the old timestamp as historical grouping data, not a new timer, and preserve all previous holds and counters. Actual credential, pricing and provider-capability freshness still matters.
- A Stop label must describe the reservation boundary honestly. Finishing a current reserved request can include dispatching it; preserve its observed outcome and accepted audio before refusing the next reservation. Do not claim immediate cancellation or a no-post-click-dispatch guarantee.
- A pure split compiler is not an implemented automatic recovery workflow. Native admission, child identity, retained holds, exact coverage, interruption recovery and assembly must all be wired and tested.
- Long Audio is an asynchronous operation, not an immediate base64 response. Persist POST-once state before dispatch, retain the exact operation resource, resume by GET only, and verify private storage output before calling it accepted media. Polling completion alone is not a verified MP3.
- Verify the actual installed visible journey, including the primary action, cost/reuse review, progress, actionable failure, playback and export. Synthetic audio proves local workflow only; label it clearly.
- Prepare reusable work before starting a short authority window. Preserve immutable checkpoints and backups across crashes. Reconcile uncertain installer, publication and provider outcomes before retrying.

Source-only additions or fake-provider tests are not evidence of an installed fix or successful live narration. Release notes must state those distinctions.
