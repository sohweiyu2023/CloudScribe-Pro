# Completion interpreter binding recovery

This is an explicit, independently reviewed executable-binding transition. It does not disable exact hashes, accept arbitrary publishers, grant spending authority, or repair an expired narration window.

The installer accepts one typed `interpreter-binding` transition only for an active, pre-effect whole-article scope: no catalog refresh, financial admission, reservation, or other pending operation. Application binaries, interpreter path, account, project, profile, immutable plans, original six-hour window, and counters remain bound. The new executable requires its exact reviewed SHA256, Python version, file size, path digest, and valid Python Software Foundation Authenticode signer/thumbprint. Separate repair approval evidence must differ from the narration approval.

The journal records the repair before any control-file switch. Complete predecessor gate, installation-marker, and profile-required-marker backups are verified first. Interrupted updates remain blocked; only the exact pending transition can reconcile the reviewed old/new states. A partial audit backup fails closed rather than silently proceeding.

## Terminal withdrawal

`Restore-CompletionInterpreterBinding.ps1` performs a separately approved, safety-only withdrawal. The exact repair, backup byte hashes, profile, binaries, scope, and zero-effect state must match. A durable terminal withdrawal claim stops normal effects **before** restoration. Every atomic control-file replacement is bracketed by a fresh check. Completion requires all three original files byte-for-byte and leaves the run permanently stopped. History, deadlines, financial holds, and the consumed repair allowance are retained.

This returns to the original integrity-blocked state. It is **not a working narration rollback** if the old interpreter bytes are unavailable. It never executes the old interpreter, clears the stop, resets counters, releases holds, or restores paid permission. Obtaining an operational previous runtime requires independently verified original executable bytes and a separately reviewed restoration; it is not inferred from the backups.

Elapsed expiry permits only terminal withdrawal, never forward repair or narration. Backward clocks, monotonic reset, unknown outcomes, changed identities, active financial policies, and conflicting pending operations fail closed. Same-epoch register reopen is tested; this does not establish OS-reboot recovery.

An expired whole-article scope is never renewed in place. The separately typed `whole-article-interpreter-continuation` handoff permits one distinct successor only when the original whole-article scope had zero refreshes, admissions, build transitions, or repairs. It requires a different narration approval and whole-article grant plus separate exact interpreter-binding approval. The original register and clock anchors remain unchanged; retirement and activation append audit records. An observed postboot monotonic discontinuity is recorded only while retiring expired authority, never used to revive it. The ancestor chain remains cycle checked and bounded to five registers. A second such interpreter successor is rejected. The new scope starts with zero admissions; installing it is not paid-generation permission. Any financial policy requires its own exact reviewed admission. Terminal withdrawal restores the old control bytes but leaves both the retired predecessor and the withdrawn successor unable to dispatch.

## Verification boundaries

Tests use synthetic SQLite profiles, inert app binaries, fake service data, and no provider calls or credential-store operations. Core and actual isolated CLI tests cover forward repair, expiry, clock rollback, tamper, replay, concurrency, pending/completed withdrawal, and each partial restoration boundary. PowerShell tests invoke production functions against synthetic destinations; signature responses are mocked. Real publisher verification and a production installation are separate release gates. `-ValidateOnly` is read-only and cannot be combined with pending withdrawal completion.
