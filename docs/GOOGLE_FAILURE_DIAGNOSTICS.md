# Safe Google synthesis failure diagnostics

HTTP status and canonical `error.status` are recorded independently from queue admission decisions. A completed error response does not prove no charge and does not authorize retry. Keep existing reservations and inspect the durable request identity before any separately approved recovery.

Local event 1604 additionally records fixed enum categories derived from `google.rpc.ErrorInfo` and `google.rpc.BadRequest`, when the provider actually supplies those structured details. Parsing is bounded to 16 KiB, JSON depth 8, 16 detail entries and 16 field violations. Duplicate or malformed consumed fields produce Unknown. Unsupported values never become log strings.

The reason allowlist covers documented Service Infrastructure reasons in the `googleapis.com` domain: service/billing disabled, invalid or service-blocked API key, rate/resource quota exceeded, invalid consumer, expired token and insufficient token scope. Domain categories recognize only `googleapis.com` and `texttospeech.googleapis.com`; service-specific reasons without an explicit allowlist remain Unknown. Request-field categories recognize the fixed text/SSML, voice and audio-configuration field names. Multiple recognized fields become Multiple. Unknown fields become Unknown. These categories are diagnostic only, never synthesis permission, retry evidence or budget settlement.

The canonical parser never derives a canonical reason from `error.message`. Event1607 separately records bounded parse/shape metadata: status/message presence and type, message UTF16 length, absent/empty/recognized/unrecognized/mixed detail types, and a fixed local informational message hint. Unknown detail types are distinct from missing details. Malformed, ambiguous, invalid UTF8/escaped Unicode, oversized or excessively deep data suppresses hints. Recognized detail field shapes are checked without retaining their values.

The message hint recognizes only a few anchored validation phrases, including generic invalid-argument wording and a reported sentence-length validation. It is not the canonical provider reason, a numeric sentence limit, proven root cause, permission to rechunk/retry, or billing evidence. Unmatched text stays Unrecognized. Raw messages, field descriptions, metadata, localized messages and raw details are never logged or hashed. Earlier discarded message text cannot be recovered, and old NotProvided values do not prove all structured details were absent.

Event1605 records the hash and UTF8 byte count of one owned request-content snapshot used by `ByteArrayContent`, taken before credential resolution. Deliberate caller-array mutation during a delayed credential await cannot change that snapshot. Endpoint identity consists only of a known route enum, pinned-origin hash and query-presence flag; no URI, path, query value or header is logged. This identifies managed HTTP content, not a packet capture or proof of historical per-attempt URIs. A request below the existing5,000-byte compiled-envelope guard should not be blamed on that cap without an actual wire invariant failure. No undocumented sentence-length limit is imposed. One successful part does not certify all Chirp requests.

Event1606 records response bytes consumed, completion/failure/cancellation/overflow, media-type category and declared-length presence/match category. Declared Content-Length is captured from bounded nonvalidated header values before any getter can compute or replace it; raw header values are discarded. Completed responses and interrupted reads remain distinct. Supplemental diagnostic sink failures do not change the provider result. Canonical malformed-Unicode values now become Unknown instead of escaping unhandled; HTTP policy, sticky dispatch claims, grant consumption and all reservations remain enforced. Fake400/429/503 recovery tests verify no automatic replay, release or second submission.

All new values are local enum/bool/integer metadata plus existing request/correlation hashes. They use the existing bounded rotating JSON log sink. No response-body/message hash, credentials, article/audio contents or personal paths are added. Actual data is retained only when local Information logging is enabled. Offline tests inspect both formatted and structured state and the production file sink in an isolated synthetic profile. This improves future evidence; it does not promise the provider will supply an actionable explanation.
