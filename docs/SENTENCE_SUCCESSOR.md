# Sentence-grouped article continuation

This offline planner keeps complete existing sentence units together, grouping them within the existing local 333-scalar bound. That bound is a planning heuristic, not a provider sentence threshold or acceptance guarantee. It preserves exact text, order, accepted ranges and Unicode text elements. Missing runs starting after accepted audio isolate their inherited partial first sentence. Oversized individual sentences fail closed rather than silently falling back to arbitrary clauses. Bare newlines and ambiguous ASCII periods are not assumed to be sentence endings.

`CompileSentences` creates a proposal for an unstarted article. It cannot replace another stored root. `CompileSentenceSuccessor` embeds one exact existing predecessor, which may itself have the existing one-failed-range refinement. Runtime admission revalidates the full bounded chain, native revision, historical attempts, account/project, queue outcomes, finalized receipts, execution mapping and media hashes. It preserves every inherited/direct accepted range exactly once. Pending/uncertain work and contradictory failed states with accepted/recoverable output prevent continuation. Stored/export selection uses one complete immutable chain, never newest-by-time selection. SQL reads include an extra row to detect an over-limit chain.

Financial reservation, claim, duplicate, expiry and whole-article execution guards are unchanged. A proposal, deterministic payload or compiler hash grants no spending authority. A new reviewed policy must name the exact new plan, financial baseline, allowed requests and whole-article grant. No automatic paid retries or accepted-audio regeneration are introduced. Existing serialized plans omit the new null field and retain their previous bytes/hash.

## Delivery limitations

The local fake-provider tests exercise preparation, admission, durable jobs, successful receipt reuse across two generations, complete ordered coverage, export and restart deduplication. They do not establish Google acceptance, natural-sounding joins or native UI acceptance of a released package. A failed passage can contain complete sentence units that remain unchanged after regrouping; this may retain the provider's unidentified offending sentence.

The typed schema-4 handoff now retires one exact schema-4 predecessor and activates a schema-5 sentence plan inside the SAME immutable UTC window. It carries used refresh/admission/resume counts, proves the original head, closed financial database, confirmed failed attempt, complete native/legacy accepted receipts and audio pins, and freezes the new budget/manifest. A previously successful, byte-pinned admission may be read as historical provenance after its expiry only after its installed pin and successful journal record verify. It supplies no new authority: every outer resume policy, exact clean held attempt and current clock/build/identity still require fresh validation. Its first admission names exactly two representative requests; the remaining admission is rejected until both actual successful receipt/output/mapping/media records verify. Interrupted claims remain unresolved until exact readback; restoring predecessor control files cannot reactivate retired authority. Existing clock and ordinary continuation guards remain strict.

A distinct `same-window-sentence-replan-after-reboot` handoff is available only for separately approved retirement of a reboot-blocked epoch. It does not resume or repair old authority. Before the first claim, independently reviewed evidence must pin the old last-good UTC/head, Windows boot readback hash, current native UTC/monotonic pair and an independent UTC interval no wider than five seconds. Evidence older than ten minutes cannot start retirement. The hash alone does not authenticate a boot or grant permission: the operator must obtain and independently review the actual evidence under specific approval. A second clock reset, pending/uncertain work, unknown stop, changed identity/counters, old future-valued UTC or expired original window stays blocked. A future-valued old `lastUtc` is intentionally unsupported; no OS clock correction is performed.

The new register binds the observed pair permanently. Its conservative independent upper UTC plus elapsed monotonic time cannot reach the original deadline. Native policy expiry is additionally shortened by the independent UTC uncertainty and a 250 ms safety margin; all new policy claim/installed readback/verification paths enforce that earlier cutoff. No new six-hour window, funds release, clock adjustment, counter reset, implicit approval or paid retry is introduced. Publication, release, live transition and revised spending admission remain separate gated operations. Synthetic tests cannot establish provider acceptance or real machine boot provenance.

## Separately approved window after terminal expiry

`expired-terminal-sentence-replan` is a distinct schema-4-to-5 handoff for a future explicitly approved run after the old window has expired. It is never an ordinary renewal. Its required `WindowApprovalSha256` must match the new scope/source approval, which must differ from the predecessor approval; an arbitrary hash or synthetic fixture is not human authorization. Independent review must verify that the referenced approval actually covers the exact new window, plan, preserved accounting, spending bounds and limits. No production scope or approval is shipped with source.

The old window must be proven expired by the independent UTC LOWER bound. A fresh native UTC/monotonic observation pins the new start and exactly six-hour end; the same derivation is enforced during retirement replay, pending recovery and runtime. Boot metadata is retained, but retirement of expired authority does not falsely claim that a reboot occurred. The explicit same-window reboot kind keeps its stronger boot-after-last-good requirement. The new native policy cutoff remains conservatively earlier for UTC uncertainty.

Nonzero historical activity is allowed only with the existing full terminal-failure, financial, accepted-output and zero-pending/uncertain proofs. The old scope, events, holds, used refresh/admission/resume counters and terminal outcome remain intact. The new register carries used counters; consumed slots do not become available again. Failed, unknown or submitted-but-unreconciled work cannot be translated into new permission. Exact interrupted activation can reconcile once before the new deadline, while replay, future old UTC, another clock reset, stale observation or missing fresh approval blocks it. This single legacy-4-to-natural-5 transition does not enable recursive window renewal.


Installation must use the normal backed-up installer only after release checks. Rollback restores the prior binaries/configuration, preserving all profiles, audio and append-only financial/history records. It cannot erase new receipts or resurrect expired paid authority. No live installation or provider operation is part of these development tests.
