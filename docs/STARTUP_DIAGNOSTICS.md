# Startup timing diagnostics

Local structured event1020 records a fixed startup phase/state, phase elapsed milliseconds, elapsed milliseconds since the managed startup observer was created, and the backend deadline state/remaining milliseconds. It records no assembly names, file paths, command-line values, document/audio contents, credentials or exception bodies. Dependency-resolution phase duration is not proof of assembly loading, JIT, disk activity or resource contention.

The observer retains at most64 records per managed process. Early bootstrap/composition/core-resolution timings buffer in memory until the existing bounded structured logger is ready. They add no synchronous per-phase bootstrap file writes. If startup fails before a logger is available, the existing best-effort fatal bootstrap path receives one bounded summary of these typed pending records. An externally terminated process may lose those unflushed early records; this instrumentation is not an external process profiler.

Phases distinguish bootstrap logging setup, host composition, core dependency resolution, diagnostic-directory setup, primary-instance acquisition, host startup, initializer dependency resolution, application initialization, STA desktop-thread scheduling, framework initialization, main-window dependency resolution and framework readiness. The scheduling marker measures the RunAsync call through entry to its STA callback, including completion-source/thread construction, STA setup and Thread.Start; it is not pure scheduler latency and does not insert or measure an Avalonia dispatcher queue job. Framework readiness is the existing ApplicationReady signal, not a first-frame or audible-playback claim; existing native opened/first-render/settled events remain separate.

BackendBudget records when the existing configured startup deadline is armed, disarmed or observed expired. The observer does not create, extend, reset or cancel any timer. As before, host construction/early diagnostics precede that deadline, and the deadline is cancelled before desktop initialization. A remaining value of-1 means the backend deadline is not currently armed; desktop startup therefore need not fit the backend20-second default. OS/apphost/CLR time before managed entry is outside the observer's elapsed origin.

Sequence numbers retain ordering if early buffered records and later cross-thread records reach the sink out of order. Once the64-record cap is reached, extra timing observations are dropped without changing application work. Sink failures must not replace startup outcomes. The existing logger retains its file/directory/queue bounds and local-only policy.

These markers address missing evidence around a recorded startup timeout. They do not fix that timeout, prove its cause, justify disabling backup/integrity checks, or resolve the historical crash. The isolated database probes did not reproduce the delay. No provider call, live-profile change, cold-cache manipulation, security change or artificial app failure is needed to validate this diagnostic-only change.
