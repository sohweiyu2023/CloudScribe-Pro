What changed
------------
AtomicVerifiedRestoreExecutor now fails closed before creating or writing a restore destination when the configured restore root traverses an existing symbolic-link/reparse-point ancestor. If the restore root does not yet exist, the executor walks to its nearest existing ancestor, validates that ancestor and every filesystem ancestor as physical/non-reparse, and only then creates the restore directory. It revalidates the resulting restore root after creation.

Focused regression coverage creates a restore root beneath a directory symbolic link to an external directory and verifies that execution throws before the external restore directory or restored file can be created.

Why this matters
----------------
RestoreRecoveryTerminalVerifier already rejects reparse-point ancestors at terminal verification. The write executor previously validated the restore root itself but not all pre-existing ancestors before Directory.CreateDirectory/write publication. The new boundary check prevents any restore-side effect from crossing an ancestor reparse point instead of relying on the later terminal verifier to catch it.
